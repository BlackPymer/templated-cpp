# Лабораторная работа №4. Обобщённое программирование: сортировка и контейнеры

C++17-реализация лабораторной работы №4 по дисциплине «Проектирование
программного обеспечения интеллектуальных систем». Выполнены обе
обязательные части задания:

| Часть | Вариант | Реализация |
|---|---|---|
| Задание 1. Сортировка | 2 — Cocktail sort, Strand sort | `include/cocktail_sort/`, `include/strand_sort/` |
| Задание 2. Графы | 2.1.2 — ориентированный граф на матрице смежности | `include/oriented_graph/` |

## Структура проекта

- `include/cocktail_sort/` — обобщённая сортировка перемешиванием и
  демонстрационные типы `TestType`, `TestContainer`;
- `include/strand_sort/` — обобщённая strand-сортировка;

- `tests/` — модульные тесты UnitTest++ (92 теста);
- `.github/workflows/ci.yml` — сборка, тесты, покрытие, линтер и релиз;

- `scripts/lint.sh` — локальный запуск clang-format и clang-tidy.

## Задание 1. Обобщённые сортировки

### CocktailSorter

Шаблонный класс `CocktailSorter<Iterator>` реализует сортировку
перемешиванием (двунаправленную пузырьковую сортировку). Параметр шаблона —
тип итератора, поэтому алгоритм работает и с обычными массивами, и с
`std::vector`, и с пользовательскими контейнерами. Элементы сравниваются
оператором `<`, что позволяет сортировать как встроенные типы, так и
пользовательские классы.

```cpp
std::vector<int> values = {5, 1, 4, 2, 3};
CocktailSorter<std::vector<int>::iterator> sorter;
sorter.Sort(values.begin(), values.end());
```

### StrandSorter

Шаблонный класс `StrandSorter<Iterator>` реализует strand sort: из входной
последовательности выделяются возрастающие подпоследовательности, которые
затем сливаются в общий результат. Тип значения определяется через
`std::iterator_traits`, поэтому сортировка также работает с массивами и
стандартными контейнерами.

```cpp
int values[] = {5, 1, 4, 2, 3};
StrandSorter<int *> sorter;
sorter.Sort(values, values + 5);
```

### Демонстрационные типы

- `TestType` — пользовательский класс с полями `value` и `id`, операторами
  `<`, `==`, `!=` и выводом в поток; используется для сортировки объектов;
- `TestContainer` — собственный контейнер на основе `std::vector<int>` с
  публичными псевдонимами типов; используется для проверки работы
  сортировки с нестандартной коллекцией.

## Задание 2. Ориентированный граф на матрице смежности

`OrientedGraph<T>` — шаблонный контейнер с одним параметром типа,
задающим тип значения вершины. Внутреннее представление (вектор вершин и
матрица смежности) скрыто в закрытой секции; наружу предоставляются только
методы и итераторы.

Публичные псевдонимы типов: `value_type`, `reference`, `const_reference`,
`size_type`, `difference_type`, `edge_type` (`std::pair` из двух вершин),
`container_type`, `matrix_type`, а также типы итераторов.

Реализованные операции:

- конструктор по умолчанию, копирующий и перемещающий конструкторы,
  копирующее и перемещающее присваивание, деструктор;
- `empty()`, `clear()`, `size()`, `edgeCount()`;
- `contains()`, `indexOf()`, `at()` с проверкой диапазона;
- `hasEdge()`, `degree()`, `edgeDegree()` (петля имеет степень 1,
  обычное ребро — 2);
- `addVertex()`, `addEdge()`, `removeVertex()`, `removeEdge()`,
  удаление вершины и ребра по итератору;
- сравнение графов операторами `==`, `!=`, `<`, `>`, `<=`, `>=`;
- текстовое представление через `operator<<` и `std::for_each` по
  итераторам.

### Итераторы

Для каждой сущности графа реализованы двунаправленные итераторы,
удовлетворяющие требованиям STL:

- `VertexIterator<Const>` — перебор вершин;
- `EdgeIterator<Const>` — перебор всех рёбер;
- `NeighborIterator<Const>` — перебор вершин, смежных заданной;
- `IncidentIterator<Const>` — перебор рёбер, инцидентных заданной вершине.

Для всех итераторов предусмотрены изменяемые и константные версии, а
обратные итераторы построены через `std::reverse_iterator`. Итераторы
поддерживают `*`, `->`, префиксный и постфиксный `++`/`--`, `==`, `!=`.

### Исключения

- `GraphException` — базовый класс;
- `NoSuchVertexException` — вершина не найдена;
- `VertexAlreadyExistsException` — повторное добавление вершины;
- `IndexOutOfRangeException` — выход за границы;
- `EdgeAlreadyExistsException` — повторное добавление ребра;
- `NoSuchEdgeException` — ребро не найдено.

## Тесты и покрытие

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Или с покрытием:

```bash
cmake -S . -B build-cov -DCMAKE_BUILD_TYPE=Debug -DLAB4_COVERAGE=ON
cmake --build build-cov -j
./build-cov/lab4_tests
cd build-cov
ROOT=$(cd .. && pwd)
gcovr --root "$ROOT" --filter "$ROOT/include/" --filter "$ROOT/src/" \
      --exclude '.*/src/main.cpp' --fail-under-line 90 --print-summary
```

Тесты проверяют:

- сортировку пустых, одноэлементных, уже отсортированных и обратных
  последовательностей;
- работу с массивами, `std::vector` и `TestContainer`;
- сортировку пользовательских объектов `TestType`;
- все операции графа, степени вершин и рёбер, петли;
- все виды итераторов, обратные и константные версии;
- копирование, сравнение и текстовый вывод графа;
- выброс исключений во всех ошибочных ситуациях.

Текущий результат: **92 теста, 100 % покрытия строк** (688 из 688 строк,

## CI/CD

Workflow `.github/workflows/ci.yml` запускается при push в `main`, при
pull request и при создании тега `v*`. Пайплайн выполняет:

1. **lint** — `clang-format` (версия закреплена в `.clang-format-version`)
   и `clang-tidy` по исходникам и тестам;
2. **build** — сборку с `-Wall -Wextra -Wpedantic -Werror` и запуск тестов;
3. **coverage** — сборку с инструментацией, запуск тестов и проверку
   покрытия `gcovr` с порогом 90 %;
4. **package** — сборку релизного бинарника `lab4`, упаковку в архив и
   сохранение артефакта;
5. **release** — при push тега `v*` архив прикрепляется к GitHub Release.

Готовый архив из Releases запускается без сборки:

```bash
tar -xzf lab4-linux-x86_64.tar.gz
./lab4
```
